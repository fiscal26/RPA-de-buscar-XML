# Fluxo de trabalho do Codex

- Use `main` como referência das últimas atualizações do projeto. Antes de cada rodada, leia a versão atual de `main` e confira as mudanças desde a base da branch de trabalho.
- Use a branch geral `codex/trabalho` para as alterações do Codex. Se ela não existir, crie-a a partir da `main` atual.
- Incorpore as atualizações de `main` na branch de trabalho antes de novas alterações. Preserve mudanças pendentes; não sobrescreva nem redefina a branch à força.
- Faça alterações e validações na branch de trabalho e abra ou atualize um pull request para `main`.
- Só faça o merge após aprovação explícita do usuário para as alterações apresentadas. Não habilite merge automático.
- Ao entregar, informe o pull request, os testes realizados e o endereço do preview da Vercel quando disponível. Diferencie o preview da publicação em produção.
